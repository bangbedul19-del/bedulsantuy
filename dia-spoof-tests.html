History / Navigation API

pushState path change

Calls history.pushState to change the visible path without navigation. Origin stays the same — check what Dia shows in the bar.

→ Bar should still reflect real origin

replaceState URL change

Uses history.replaceState to swap the current URL entry. Same-origin — verify Dia updates the bar promptly and accurately.

→ Bar should update to new path

Rapid navigation race

Fires multiple pushState calls in fast succession. Tests whether URL bar can briefly lag, showing stale URL while new content loads.

→ Look for brief wrong URL during transitions

Popup & Window

Chromeless popup

Opens a popup via window.open(...,'popup') with size constraints. Does Dia show the origin in the popup's address bar or omit it?

→ Popup bar should show blob: or artifact origin

about:blank + write()

Opens about:blank then injects HTML via document.write(). What origin does Dia display? Should be about:blank, not opener's origin.

→ Bar should remain about:blank

Opener-navigated popup

Opens popup, then navigates it to a blob: URL via popup.location.href. Verify Dia's bar updates correctly after opener-triggered navigation.

→ Bar must reflect final URL after navigation

Special URI Schemes

data: URI display

Opens a data:text/html page in a new tab. Dia should show the full data: URI or a null origin — not a spoofed domain.

→ Bar: full data: URI or null origin

blob: URL origin

Creates a blob: URL from this origin and opens it. Dia should show blob:<origin>/... — the generating origin must be visible.

→ Bar: blob:<this-origin>/uuid

javascript: link test

A javascript: href that replaces page content should not leave the old origin showing in the bar. Test link is created but not auto-followed.

→ Navigate link manually; bar should update

URL Display Edge Cases

Long URL truncation

Sets a very long path via pushState. Check if Dia's truncation hides the true path in a misleading way (e.g. truncating before /admin).

→ Full origin must remain visible

Userinfo@host pattern

The URL https://site.example@attacker.test/ should display attacker.test, not site.example. Manual test — enter in Dia's bar directly.

→ Displayed host must be attacker.test

Fragment navigation

Changes the URL fragment via location.hash. Encoded separators in the hash should not be decoded in a way that changes the perceived path.

→ Origin must not change

Fullscreen & UI Chrome

Fullscreen URL bar visibility

Enters fullscreen. In some browsers the URL bar disappears entirely. If so, a custom fake bar drawn by the page could replace it.

→ Does Dia show any origin indicator in fullscreen?

Fake URL bar overlay

Draws a fixed-position fake address bar at the top of the page. In normal mode it sits below the real bar. In fullscreen, if the real bar hides, this overlay becomes credible.

→ Combine with fullscreen test above

Scroll + fixed overlay

Scrolls to a position where a sticky element covers the top of the viewport. Tests if Dia's address bar is obscured by overlapping page content.

→ Real browser bar must remain above page content
